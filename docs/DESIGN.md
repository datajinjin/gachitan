# 같이 탄 만큼 — 설계 근거

## 1. 제품 방향

### 세 방향 비교

| | A. 동승 구간 정산 | B. 여행 공동 장부 | C. 정기 카풀 장부 |
|---|---|---|---|
| 핵심 | 중간에 타고 내린 운행을 탄 만큼 나눔 | 여행 경비 전체를 한 장부로 | 같은 멤버의 출퇴근을 월 단위로 |
| 차량 데이터 의존 | 높음(좌석·거리 없으면 가치 소멸) | 낮음(경비가 대부분, 차는 연료비 하나) | 중간 |
| 대안과의 차이 | 폰 앱은 구간 경계를 모름 | 토스 모임·정산 앱과 겹침 | 매일 '누가 탔나'를 사람이 입력해야 함 |
| 재사용 | 태워 줄 때마다 | 1년에 몇 번 | 높음, 그러나 대상이 좁음 |
| 설정 수고 | 이름 1탭(생략 가능) | 경비마다 입력 | 멤버 등록·매일 확인 |

**선택: A.** 차량 데이터가 없으면 사라지는 가치가 가장 크고, 운전 중 조작 없이 끝나는 유일한 방향입니다.
B의 공동 경비와 C의 월 단위 정산은 A를 보조하는 기능(여행 묶음 정산, 이번 달 사람별 합계)으로 넣었습니다.

### 핵심 가치

> **중간에 타고 내린 사람이 있어도, 차가 기록한 좌석과 거리로 각자 탄 만큼만 나눈다.**

### 자동과 확인의 경계

| 자동(차가 함) | 사람이 확인 |
|---|---|
| 구간 경계(좌석 신호 × 계기판) | 누가 앉았는지(센서는 사람을 모름) |
| 에너지비 추정(효율 → 잔량 → 기본값) | 정차 뒤 같은 좌석에 다시 앉은 분이 같은 사람인지 |
| 통행료 분담자 기본값(방금 달려온 구간) | 통행료 금액, 분담자 변경 |
| 주행 중 기록·잠금 | 정산 확정(확인 필요 항목이 남으면 확정 불가) |

## 2. 대표 시나리오: 퇴근 카풀

| 단계 | 사용자 행동 | 차량 데이터 | 화면 | 얻는 가치 |
|---|---|---|---|---|
| 출발 전 | 좌석을 눌러 최근 동승자 이름 1탭(생략 가능) | 좌석 점유, 계기판 | **출발 전**: 좌석 배치가 중심 | 준비 5초 |
| 출발 | 기어 D | 기어 | **기록 중**: 거리와 탄 사람만 크게, 버튼 없음 | 주행 중 조작 0 |
| 중간 하차·탑승 | 정차 → 내리고 타기 | 좌석 변화 지점의 계기판 값 | **정차 중**: 바뀐 좌석, 새로 탄 분은 '이름 없음' | 구간이 자동으로 나뉨 |
| 톨게이트 지나 정차 | 통행료 입력 | 방금 달려온 구간의 탑승자 | 기본 분담자가 미리 선택됨 | 내린 사람도 빠지지 않음 |
| 도착 | **운행 끝내기** | — | **정산 확인**: 사람별 탑승 막대와 금액 | 왜 이 금액인지 한눈에 |
| 확인 | 이름 없는 줄을 눌러 이름, 재탑승 확인 | — | 확인이 남으면 확정 버튼이 잠김 | 불확실한 기록을 사실처럼 처리하지 않음 |
| 확정 | **정산 확정** | — | **정산 완료**: 보낼 사람 목록 + 개인 QR | 동승자는 설치·가입 없이 카메라로 송금 |

## 3. 디자인 기준

Pleos 기본 화면(밝은 흰 바탕)과 이어지도록 흰 바탕에 블루 한 가지를 씁니다. 차량이 야간 설정이면 어두운 화면으로 바뀝니다. 대비는 WCAG 상대 휘도로 계산한 값입니다.

| 요소 | 값 | 근거 |
|---|---|---|
| 배경·면 | 배경 `#FAFBFD`, 면 `#FFFFFF`, 보조 면 `#F0F5FC`, 구분선 `#DCE3ED` | 그림자·그라데이션 없이 선과 면 두 단계로 구조 |
| 글자 | 본문 `#202630`(14.7:1), 보조 `#596575`(5.4:1 이상) | 옅은 회색 글자를 쓰지 않음. 보조 글자도 4.5:1 이상 |
| 블루 | `#2463EB`(흰 글자 5.2:1) — 주 행동, 선택, 탑승 좌석, 기록 중 표시에만. 작은 블루 글자는 `#1D4FD0`(6.0:1 이상), 선택 배경 `#E8F0FE` | 화면 전체를 파랗게 칠하지 않음 |
| 주의색 | `#8A5300` / 배경 `#FFF4E0`(5.8:1) — 확인 필요·연결 문제에만 | 상태 구분 |
| 형태 선 | 빈 좌석 점선 `#8A96A5`(3.0:1), 차 윤곽 `#C3CCD8`(장식) | 빈 좌석은 점선 + "—" 로, 색 없이도 구분 |
| 글자 단계 | 중심 숫자 96~128sp(창 크기에 따라), 48 / 36 / 32 / 28 / 24 / 22 / 20sp, 숫자는 tnum, 최소 20sp | 1~2초 안에 읽힘. 작은 창에서도 글자를 줄이지 않음 |
| 버튼 | 주 80dp(블루 채움), 보조 64dp(흰 면 + 테두리), 화면 이동은 블루 글자 + › | 한 화면 주 행동 1개 |
| 배치 | 넓은 창(너비 760dp 이상·높이 440dp 이상): 왼쪽 중심 요소 | 오른쪽 정보 위·행동 아래, 두 칸 모두 높이를 꽉 채움. 좁은 창: 세로로 쌓아 스크롤, 행동 하단 고정 | 화면 아래가 비지 않게 함 |

화면별 중심 요소: 탑승 = 좌석 배치도 / 주행 = 이동 거리 / 정산 = 총액(오른쪽 사람별 부담액) / 공유 = 한 사람 금액과 QR / 기록 = 날짜별 목록.

### 공통 컴포넌트
`theme/Theme.kt`(색·글자·간격·창 기준), `components/Primitives.kt`(버튼 4단계, 상단바, 하단 메뉴, 상태 알약, 사람 아이콘, 구분선, 입력), `components/SeatPlan.kt`(차 윤곽 + 좌석, 운전석 왼쪽 앞), `components/SegmentBar.kt`(거리 비율 그대로의 구간 막대), `screens/Root.kt`의 `PaneLayout`(두 칸/세로 배치).
