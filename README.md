# 같이 탄 만큼

> 중간에 타고 내린 사람이 있어도, 차가 기록한 좌석과 거리로 각자 탄 만큼만 나눕니다.

카풀, 친구 데려다주기, 여행처럼 중간에 타고 내리는 운행에서 좌석 탑승 신호와 계기판 누적거리로 구간을 나누고, 구간마다 탄 사람끼리 비용을 나누는 Pleos Connect 앱입니다.
운전 중에는 아무것도 누르지 않습니다. 정차한 뒤 탑승 막대를 보며 확인하고, 동승자는 앱 설치 없이 QR로 자기 몫만 받아 갑니다.

| 바로 보기 | |
|---|---|
| 실행 파일(APK) | `apk/N분의1_같이탄만큼_release.apk` (v1.5.0) |
| 테스트 환경 | Pleos Connect 에뮬레이터 v2.1.0 (API 34), 화면 2560 × 1440, 160dpi, Cold boot |
| 차량 없이 보기 | 탑승 화면의 **차량 없이 체험**, 또는 설정 → 시연 모드 → **시뮬레이터** |

## 1. 주요 기능

| 기능 | 내용 |
|---|---|
| 앉은 기간 단위 기록 | 좌석 탑승 신호로 누가 언제부터 언제까지 앉았는지 기록합니다. 같은 좌석에 다른 사람이 앉아도 앞사람 기록은 바뀌지 않습니다. 센서는 '앉았다'만 알기 때문에 이름은 사람이 정하고, 정차 뒤 다시 앉으면 앞사람 이름을 제안하되 확인 전에는 확정하지 않습니다. |
| 구간별 정산 | 승하차가 있을 때마다 구간을 나누고, 구간마다 그때 타고 있던 사람끼리 나눕니다. 정산 화면에서 사람마다 실제로 탄 구간이 막대로 보입니다. |
| 차량 데이터로 비용 계산 | 전기차는 배터리 잔량·전비, 내연기관차는 연료량·연비만 조회합니다. 효율을 받지 못하면 잔량 감소량이나 설정한 기본 효율로 계산하고 '추정액'으로 표시합니다. 중간 충전분은 빼고 계산합니다. |
| 통행료·주차비 | 기본 분담자는 방금 달려온 구간에 타고 있던 사람입니다. 직접 바꿀 수 있습니다. |
| 차량 유지비(선택) | km당 30·50·100원을 에너지비와 같은 방식으로 나눕니다. 기본은 끔. |
| 여행 묶음 정산 | 여러 날의 운행비와 숙박·식비·카페·입장료 등을 낸 사람과 나눌 사람을 따로 기록하고, 사람별 받을 돈·보낼 돈과 송금 목록(n명이면 많아야 n-1번)으로 정리합니다. 주유·충전 영수증은 차량 비용과 겹치지 않도록 경비로 받지 않습니다. |
| 반올림 | 동승자는 10원 단위로 맞추고 차액은 운전자가 부담합니다. 동승자 합계는 실제 비용을 넘지 않습니다. |
| 송금 요청 | 사람별 QR에는 그 사람 몫만 담습니다. 토스 아이디를 설정하면 금액이 들어간 송금 링크가 됩니다. 앱은 결제를 처리하지 않습니다. |
| 이번 달 사람별 합계 | 기록 탭에서 동승자별 횟수·거리·금액, 남은 금액을 봅니다. '받음 표시'와 '요청 복사'(합계 + 송금 링크)를 제공합니다. 여행 운행은 두 번 청구되지 않게 뺍니다. |
| 운행 자동 분리 | 3시간 넘게 세워 둔 뒤 출발하면 앞 운행을 자동으로 확정해 기록에 남기고 새 운행을 시작합니다. |
| 주행 중 화면 제한 | 주행 규제 신호와 기어에 따라 주행 중에는 메뉴·버튼·금액을 숨기고 이동 거리와 탑승 인원만 보여 줍니다. |
| 야간 화면·연결 상태 | 차량의 주간/야간 설정을 따릅니다. 설정의 '차량 연결 상태'에서 신호별 연결 여부와 대체 계산 방법을 보여 줍니다. |

## 2. 화면 흐름

정차 중에는 하단 메뉴 **탑승 · 정산 · 기록**, 설정은 상단 톱니 아이콘입니다. 주행 중에는 메뉴·버튼·금액이 모두 사라집니다.

| 화면 | 중심 요소 | 주 행동 / 보조 행동 |
|---|---|---|
| 탑승(출발 전) | 좌석 배치도, 탑승자 목록 | 탑승자 확인 / 여행 시작 |
| 탑승(정차 중) | 좌석 배치도, 사람별 탄 거리 | 운행 끝내기 / 통행료·주차비, 장소 이름 |
| 주행 중 | 이동 거리와 탑승 인원 | 없음 |
| 정산 | 총액·거리·구간 막대, 사람별 부담액 | 확정하고 공유 / 계산 근거, 기록 수정 |
| 정산 공유 | 한 사람의 이름·탄 거리·금액과 QR | 다른 사람 선택, 닫기 |
| 기록 | 진행 중인 운행·여행, 날짜별 운행 목록, 이번 달 사람별 합계 | 운행 정산 상세, 받음 표시, 요청 복사 |
| 여행 | 사람별 낸 돈·받을 돈·보낼 돈, 분류별 경비 합계 | 끝내고 정산 / 경비 추가, 사람 추가 |

## 3. 실행 방법

### 3-1. APK로 실행
에뮬레이터가 완전히 부팅된 뒤(차량 화면이 뜬 뒤) 설치합니다.
```bash
adb install -r "apk/N분의1_같이탄만큼_release.apk"
```

### 3-2. 소스에서 빌드
```bash
./gradlew :core:test :app:testDebugUnitTest   # 단위 테스트 (core 50개, app 35개)
./gradlew :app:assembleRelease                # Windows: .\gradlew.bat ...
adb install -r app/build/outputs/apk/release/app-release.apk
```
Android Studio에서는 폴더 열기 → Gradle JVM 21 → 실행 대상 Pleos Connect 에뮬레이터 → Run.
에뮬레이터 만들기와 시나리오별 확인 방법은 [TESTING.md](TESTING.md)에 있습니다.

### 3-3. 테스트 환경 및 설정

| 항목 | 값 |
|---|---|
| Pleos 에뮬레이터 | Pleos Connect v2.1.0 APIs Intel x86_64 Atom System Image (API 34, Android 14) |
| 화면 규격 | 2560 × 1440, 160dpi (가로). 너비 760dp 이상에서 두 칸, 좁은 분할 창에서는 한 칸 |
| 에뮬레이터 설정 | Cold boot(Quick boot에서는 차량 신호가 끊김), RAM 4GB 이상 |
| 도구 | Android Studio, Gradle JVM 21, Gradle 8.10.2, AGP 8.8.2, Kotlin 2.0.0, compileSdk 35 |
| Pleos SDK | Vehicle 2.3.2, NaviHelper 3.0.5, FusedLocation 1.1.3 |
| 차량 신호 입력 | ① 앱 안 시뮬레이터 ② Virtual Console(`adb forward tcp:8088 tcp:8088`) |
| 앱 기본 설정 | 전기차, 350원/kWh, 70kWh, 5km/kWh. 설정 → 비용에서 바꿉니다 |

## 4. 시연 시나리오

설정 → 시연 모드 → 시뮬레이터를 켠 뒤 화면 아래 **▶ 시연 시나리오**를 누르면 약 25초 동안 아래 흐름이 자동으로 재생됩니다.

| 순서 | 장면 |
|---|---|
| 1 | 조수석·뒷좌석 왼쪽에 탑승, 이름 민지·준호 |
| 2 | D → 주행 화면(이동 거리·인원만) → 20km |
| 3 | 정자역 도착, P → 준호 하차, 뒷좌석 오른쪽에 새 탑승자(서연) |
| 4 | D → 25km → 판교역 도착, P → 통행료 1,200원(분담자 자동 선택) |
| 5 | 운행 끝내기 → 정산: 총액, 구간 막대, 사람별 부담액 |

시연에 나오는 이름은 모두 가상 인물입니다.

## 5. 구조

```
core/  순수 Kotlin (Android 의존 없음)
 ├─ TripRecorder   차량 이벤트 → 앉은 기간·구간·정차 지점
 ├─ Settlement     구간별 분배, 효율 이력 적용, 통행료 분담, 반올림
 ├─ TripJournal    이벤트·조작을 순서대로 저장, 재생하면 같은 상태로 복원
 ├─ TripLog        확정한 운행 기록과 저장 형식
 ├─ Journey        여행 묶음 정산, 잔액 → 송금 목록
 └─ JourneyCodec   공유 링크 형식(서버 저장 없음)

app/
 ├─ vehicle/       Pleos·AAOS 신호 연결, 시뮬레이터
 ├─ session/       운행 세션, 정산 확인 단계, 여행
 ├─ ui/model/      화면 표시 규칙(순수 Kotlin, 테스트 있음)
 ├─ ui/components/ 버튼, 좌석 배치도, 구간 막대, 시트, QR
 ├─ ui/screens/    탑승·주행·정산·공유·기록·여행·설정
 └─ ui/theme/      색·글자·간격
docs/index.html    휴대폰용 여행 정산 화면(정적 페이지)
docs/DESIGN.md     설계 근거와 디자인 기준
```

### 사용하는 API (조회 전용, 차량 제어 없음)

| 기능 | API | 권한 |
|---|---|---|
| 좌석별 탑승 | `Seat.registerSeatOccupancy`, `getCurrentSeatOccupancy` | `CAR_SEATS` |
| 계기판 누적거리 | `Odometer.registerDistanceDriven`, `getCurrentDistanceDriven` | `CAR_DRIVE` |
| 잔량·효율 | `EvBattery`·`Fuel` 등록/조회, 효율은 출발·정차 때 재조회 | `CAR_ENERGY` |
| 도착 장소 | `NaviHelper` 도착 이벤트 | `NAVI_ROUTE` |
| 출발·정차 위치 | `FusedLocation` (기어 변경 시 1회) | `FUSED_LOCATION` |
| 기어 | AAOS `CarPropertyManager` `GEAR_SELECTION` | `android.car.permission.CAR_POWERTRAIN` |
| 주행 규제 | AAOS `CarUxRestrictionsManager` | – |

| 신호 | 결과 |
|---|---|
| Vehicle SDK 초기화 | 연결됨 |
| 좌석 탑승(조수석·뒷좌석 3곳) | 연결됨 |
| 계기판 누적거리 | 연결됨 |
| 배터리 잔량(EvBattery SOC) | 연결됨 |
| 기어, 주행 규제 | 연결됨 |
| 내비 연동(NaviHelper) | 초기화됨 |
| 전비 조회 | 에뮬레이터 미지원 → 잔량 감소량·기본 효율로 계산 |
| 위치(FusedLocation) | 권한 미승인 → 장소 이름은 내비 도착 이벤트나 직접 입력 |

**단위 테스트**: core 50개, app 35개. 무작위 운행 3,000건으로 총액 보존, 운전자 부담액 0 이상, 반올림 후 합계 일치, 저장 후 재생 결과 일치를 검사합니다.

**실차에서 확인하지 못한 것**

| 항목 | 처리 |
|---|---|
| 효율 조회 반환 형식, 누적거리 단위 | SDK 문서·샘플 기준. 설정 → 차량 연결 상태에서 받은 값 확인 가능 |
| 뒷좌석 착좌 센서 유무 | 신호가 없으면 '좌석 정보 없음'으로 표시하고 사람이 정합니다 |
| 기어 권한 이름 | AOSP 기준 이름 사용 |
| 앱이 꺼져 있던 동안의 승하차 | 복원하지 않고 기록 공백으로 안내합니다 |

## 7. 개인정보

이름과 기록은 Android Keystore로 암호화해 차 안에만 저장하고 자동 백업을 끕니다. 여행 정산 공유 링크는 내용을 URL의 `#` 뒤에 담아 서버에 저장되지 않습니다. 앱은 결제를 처리하지 않습니다.
